# EOS Memory Policy v1

Status: Phase 0 policy

## Purpose

EOS memory exists to answer operational personal questions with evidence. Memory must not become a second source of truth or a raw-data warehouse.

## Allowed Sources

Allowed future memory sources:

- Google Calendar event IDs and event metadata
- Gmail message IDs and thread IDs
- Google Tasks IDs
- Vault markdown notes
- daily and weekly EOS summaries
- user-approved journal signals
- meeting briefs generated by EOS

## Source Requirement

Memory answers must include sources for factual claims whenever the answer depends on past data.

Preferred answer format:

```text
Answer:
...

Evidence:
- Calendar event ...
- Mail thread ...
- Task ...
- Vault note ...

Uncertainty:
...
```

If EOS cannot find a source, it must say that rather than guess.

## Storage Rules

Prefer storing:

- source IDs
- stable links
- timestamps
- summaries with provenance
- classification metadata
- confidence
- retrieval metadata

Avoid storing:

- full raw mail bodies
- OTPs
- password reset links
- full legal or health documents
- broad private content copied without need
- duplicated source-of-truth data

## Uncertainty Rules

EOS must distinguish:

- confirmed fact
- likely inference
- weak match
- missing source
- conflicting evidence

When uncertain, EOS should answer with the best candidate and name the uncertainty.

## Sensitive Data Rules

Sensitive content includes:

- banking and credit card data
- tax and legal content
- health content
- account recovery content
- OTPs
- login links
- private personal correspondence

Sensitive content should be minimized, not expanded. Store IDs and source links where possible.

## Retention Principles

Memory retention should be tied to operational usefulness.

Default posture:

- keep source links and summaries
- avoid indefinite raw content storage
- support future deletion or reindexing
- separate derived memory from systems of record

## Hallucination Guardrails

EOS must not:

- answer personal-history questions from memory without sources
- invent meeting summaries
- invent mail contents
- infer commitments from weak signals
- present old derived state as current source truth

## Future Implementation Requirements

Before implementing persistent memory:

- define memory tables or index files
- define source-link schema
- define retention defaults
- define redaction rules
- add tests for sourced and unsourced answers
- add tests for conflicting evidence
